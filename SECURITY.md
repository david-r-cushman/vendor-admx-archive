# Security Policy

## Supported versions

Security fixes are applied to the current default branch. Published release
tags identify archive-tooling baselines but are not independently maintained
branches.

## Reporting a vulnerability

Do not report security vulnerabilities in public issues.

When private vulnerability reporting is enabled for this public repository,
use the **Report a vulnerability** option in GitHub's Security area. Include:

- A clear description of the issue and its potential impact.
- Safe reproduction steps or a proof of concept.
- Relevant logs or error output with secrets removed.
- Suggested remediation, if available.

If private vulnerability reporting is unavailable, do not disclose the details
publicly. Contact the repository owner through a private channel and include
only the minimum information needed to establish secure follow-up.
